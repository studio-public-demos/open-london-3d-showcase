# Open London 3D Drive

Open London 3D Drive is a browser-based geospatial journey from Westminster Bridge to Trafalgar Square through Parliament Square and Whitehall. It combines an OpenStreetMap basemap, OSM-derived buildings and public-realm data, a road-aware route, and a georeferenced Three.js vehicle in one MapLibre-controlled 3D scene.

**Live demo:** https://studio-public-demos.github.io/open-london-3d-showcase/

## What the project demonstrates

- A single geographic coordinate and camera system for the basemap, route, 3D buildings, trees, and vehicle.
- A driving route generated by OSRM from OpenStreetMap road topology, including access and one-way restrictions.
- Navigation metrics derived from the same route source: distance, duration, progress, speed, ETA, and maneuvers.
- OSM building-height provenance rendered as an inspectable color layer.
- A static, key-free deployment suitable for public demonstrations and consultation prototypes.
- Responsive overview, chase, and close driving views.

## Intended value

This project is an interactive OSM-derived corridor visualization and a technical foundation for public-engagement and geospatial prototype work. It demonstrates how open data can support an understandable, browser-native spatial experience without a proprietary map SDK.

Appropriate uses include:

- Early-stage public-engagement prototypes.
- Corridor storytelling and route visualization.
- Demonstrating building-data coverage and confidence.
- Evaluating browser-based geospatial interaction patterns.
- Establishing a foundation for richer planning datasets and scenarios.

## Scope and limitations

- The route is generated ahead of deployment and is not a live turn-by-turn navigation service.
- Building footprints and heights come from OSM tags or documented estimates; this is not a survey-grade city model.
- The experience contains one route and one vehicle. It does not model traffic demand, congestion, or modal flows.
- It is not suitable for visibility, shadow, safety, engineering, or statutory planning analysis without validated terrain, structures, solar calculations, and authoritative source data.
- The OSM raster basemap requires network access. The processed corridor layers and route are hosted with the application.

## Architecture

MapLibre GL JS owns the map camera and geographic projection. Buildings, roads, water, trees, and the route are MapLibre layers. The vehicle is a Three.js custom layer rendered with MapLibre's projection matrix and shared WebGL context, keeping it aligned during zoom, pitch, bearing, and pan changes.

The route generation script requests an OSRM driving route through four corridor waypoints. The resulting geometry, steps, distance, and duration are stored in `data/processed/navigation-route.json` and consumed as one source of truth by the renderer and HUD.

## Local development

Requirements: Node.js 20 or newer.

```bash
npm install
npm run route
npm run build
node scripts/publish-build.mjs
```

Serve the repository root with any static server. For example:

```bash
python -m http.server 4173
```

The `npm run publish:local` command regenerates the OSRM route, creates the Vite production build, and publishes the generated entry point and assets into the GitHub Pages root.

## Validation

The generated route is 1,363.6 metres with a 229.7-second OSRM estimate. Its navigation steps sum to 1,363.5 metres and 229.7 seconds. Automated browser checks cover loading, WebGL rendering, drive controls, pause/restart behavior, provenance mode, GitHub Pages subpath loading, and mobile layout.
